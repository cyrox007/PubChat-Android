# Проверка восстановления соединения PubChat Android

Функция: Spaces и Messenger автоматически восстанавливают WebSocket после
обрыва. Это не относится к восстановлению уже завершённого WebRTC-звонка.

## Механика

- Android Activity сообщает контроллеру ON_RESUME / ON_STOP.
- При проблеме транспорта контроллер перестаёт использовать старый WebSocket,
  повторно получает **новый одноразовый realtime-ticket** через текущую сессию,
  восстанавливает канал и отправляет актуальную подписку.
- Паузы между попытками: 1 → 2 → 4 → 8 → 16 → 30 секунд (с ±20% jitter).
  Пока приложение в фоне, новые попытки не запускаются; при возврате на экран
  попытка производится немедленно. Возврат проверенного интернета тоже
  ускоряет повторное подключение.
- При готовности Messenger повторяются подписки на online-статусы и загрузка
  открытой переписки; Space запрашивает актуальную `initial_data`.
- При 401 после неуспешного refresh, 403/404 или WebSocket 1008/4001
  **повторение запрещено**. Права доступа не обходятся.
- При выходе из комнаты/мессенджера, logout и уничтожении контроллера
  задания отменяются и устаревшие callbacks игнорируются.
- Сообщения **не отправляются повторно автоматически**, чтобы не дублировать
  действия после сетевой неопределённости.

## Проверки на реальном устройстве (обязательно перед закрытием #32)

Запуск на двух разных моделях/версиях Android; отметить модель, Android,
способ сети, версию приложения, время обрыва и восстановления, без токенов
и содержимого сообщений.

| Сценарий | Условие успешности |
| --- | --- |
| Wi-Fi → LTE → Wi-Fi, открытый Space | Подключение возвращается, свежие сообщения приходят |
| Airplane Mode на 30 с, открытая переписка | UI показывает «Восстанавливаем связь», после восстановления приходят сообщения |
| Потеря связи на 3–5 мин | Retry не создаёт всплеск запросов; позднее подключение успешно |
| Свернуть приложение, потерять сеть, вернуться | ON_RESUME восстанавливает без повторного входа |
| Включить экран после Doze, сменить IP | После возврата в приложение связь возобновляется |
| Сервер перезапускает WebSocket | Получается новый ticket; Messenger снова подписан на статусы |
| Открыть другой Space во время retry | Старый запрос и его socket не возвращают предыдущий Space |
| Logout во время retry | WebSocket и HTTP не получают право восстановить прежнюю сессию |
| Искусственный 401 / 403 / 1008 | Нет бесконечной retry-петли; UI показывает ограничение |
| Отправка на границе обрыва | Дубликатов нет; при ошибке пользователь явно видит отказ |

Автоматика: `RealtimeRetryPolicyTest` и сборки двух CI-конфигураций (Firebase
включён / выключен). Unit tests проверяют политику повтора, но **не заменяют
device tests, network emulation и серверные интеграционные проверки**.
